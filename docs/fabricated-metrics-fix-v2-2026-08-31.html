1. What the First Pass Missed (and Why)

The v1 fix session correctly closed the fabrication in admin.ts:87-95 (now computes real active/resolved/total from actual ticket rows). But it had two blind spots:

Blind Spot A: Grep Pattern Insufficiency

The v1 session (and the queued prompt that preceded it) both relied on || N and ?? N as the fabrication pattern. This catches most sites but misses ternary defaults — e.g., totalIncidents > 0 ? ... : 71. The : 71 shape is not matched by a regex looking for || or ??.

Blind Spot B: File-Level Scope

Even within the files the v1 session did read, it stopped at the specific lines named in the prompt. It did not read the surrounding functions fully. impact/page.tsx had four fabricated values in six lines (278, 198, 71, "3.2") — all in the same function — plus two entirely fabricated data generators (generateTimeSeries() and generateProvinceData()), plus hardcoded JSX values (88.4%, 88.2%, 18.4 tonnes, 7.4 pH, 94.2% AI accuracy). A pattern match on the first two would have missed every one of these.

Lesson: Grep finds candidates; it does not prove completeness. After finding a fabrication site, read the surrounding function fully. Impact/page.tsx had fabricated values in six lines — a regex on ||/?? would only catch two of them. The ternary : 71 hides outside the literal ||/?? shape.

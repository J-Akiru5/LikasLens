1. Executive Summary

Ghost Mode in LikasLens is a privacy-preserving reporting mode designed to protect the identity of citizens reporting environmental violations in dangerous contexts (illegal logging, polluting industries, etc.). This audit evaluates whether Ghost Mode truly strips EXIF data and anonymizes the reporter.

✅ What Ghost Mode Does Well
  • EXIF stripping is defense-in-depth: Client-side Canvas re-encode removes all metadata before transmission. Server-side Imagick/GD strips again as a safety net. Both layers are functional.
  • Identity is fully decoupled: Ghost submissions are linked to a placeholder user (00000000-0000-0000-0000-000000000000) with role ghost. No real user ID, name, or email is stored.
  • No notifications leak: Ghost users never receive emails or push notifications. Timeline entries show actor: null.
  • No achievements/rewards: Ghost submissions skip gamification entirely, preventing identity correlation via reward patterns.
  • Blockchain hashing excludes identity: The evidence hash submitted to Sepolia contains only non-identifying metadata (location, type, severity).
⚠️ Where Ghost Mode Falls Short
  • Frontend sends GPS even in Ghost Mode: The frontend report page (report/page.tsx:307) includes latitude and longitude in the payload regardless of ghost mode. Only the mobile-pwa omits them.
  • No location fuzzing: There is no barangay-centroid replacement. GPS is either exact or absent — no intermediate fuzzy location exists.
  • Triple EXIF stripping (not DRY): The same Canvas re-encode logic is implemented 3 separate times across the frontend codebase.
  • Service worker queues raw data: The offline queue stores image data as-is; EXIF stripping only happens when the queued report is eventually submitted.

3. EXIF Stripping Analysis

3.1 Client-Side Stripping (Browser)

The client-side approach uses the Canvas re-encode technique: load the image into an <img> element, draw it onto a <canvas>, then call canvas.toDataURL(). The Canvas API only stores raw pixel data — all EXIF metadata (GPS, device info, timestamps, orientation) is discarded.

Technique: Canvas Re-encode
// apps/frontend/src/utils/exif-stripper.ts
export async function stripExif(base64Image: string): Promise<string> {
  const image = new Image();
  image.src = base64Image;
  await new Promise<void>((resolve) => { image.onload = () => resolve(); });

  const canvas = document.createElement("canvas");
  canvas.width = image.naturalWidth;
  canvas.height = image.naturalHeight;
  canvas.getContext("2d").drawImage(image, 0, 0);

  return canvas.toDataURL(mimeType, quality);  // Raw pixels only — no EXIF
}

This technique removes all EXIF tags including GPS, device make/model, software version, thumbnail, and orientation.

3.2 Server-Side Stripping (Laravel)

The backend applies EXIF stripping to every submission (not just Ghost Mode) as a defense-in-depth measure.

Two-Phase Server-Side Strip
// apps/backend/app/Http/ReportController.php:512-582
private function stripExifMetadata(string $imageData): string
{
    // Phase 1: Imagick (lossless — preferred)
    if (extension_loaded('imagick')) {
        $imagick = new \Imagick;
        $imagick->readImageBlob($imageData);
        $imagick->stripImage();  // Removes all metadata without re-compressing
        return $imagick->getImageBlob();
    }

    // Phase 2: GD fallback (re-encode — lossy)
    if (extension_loaded('gd')) {
        $gdImage = imagecreatefromstring($imageData);
        ob_start();
        imagejpeg($gdImage, null, 90);  // Re-encode drops all metadata
        return ob_get_clean();
    }

    // Neither available — log warning, return unchanged
    Log::warning('Neither Imagick nor GD available — EXIF NOT stripped');
    return $imageData;
}

Server-Side Pipeline (in order)

  1. Strip EXIF via Imagick (lossless) — preferred method, removes metadata without pixel re-compression
  2. Fallback: GD re-encode — if Imagick is unavailable, re-encodes as JPEG/PNG/WebP which drops all metadata
  3. Additional GD re-encode — a second GD pass for JPEG/PNG after the initial strip (belt-and-suspenders)
  4. SHA256 checksum — computed after stripping to verify integrity
  5. Timestamp recorded — exif_removed_at set on the ticket_evidence record

Source: apps/backend/app/Http/ReportController.php:82-113, 507-582

4. GPS & Location Privacy

🚨 Critical Finding: Frontend Sends GPS in Ghost Mode

The mobile-pwa correctly omits GPS coordinates from the payload when Ghost Mode is active:

// apps/mobile-pwa/src/app/[locale]/(app)/report/page.tsx:259-260
latitude: ghostMode ? undefined : gps?.lat,
longitude: ghostMode ? undefined : gps?.lng,

However, the frontend report page always includes GPS in the payload:

// apps/frontend/src/app/[locale]/report/page.tsx:307
const payload = { base64Image: cleanedImage, latitude, longitude };
// latitude/longitude are always included — no ghostMode check

Impact: A Ghost Mode report submitted via the web frontend still contains exact GPS coordinates in the API request body, even though the user's identity is hidden.

4.1 GPS Visual Stamp (Camera Overlay)

The mobile-pwa burns metadata into the image pixels as a visual overlay. Ghost Mode now correctly hides coordinates:

// apps/mobile-pwa/src/lib/camera-stamp.ts:49-54

Previously, GPS coordinates were burned into image pixels even in Ghost Mode. This was flagged as CRITICAL in the hackathon audit and has been fixed.

4.3 No Location Fuzzing

There is no barangay-centroid replacement in the codebase. When Ghost Mode omits GPS, the report has no location at all. When GPS is included (frontend bug), it's exact coordinates. There is no intermediate "fuzzy location" (e.g., snap to nearest barangay centroid) for privacy-preserving analytics.

5. Identity Anonymization

5.1 Ghost User Resolution

When a report is submitted without a valid user ID, the backend creates or retrieves a dedicated ghost user:

// apps/backend/app/Http/ReportController.php:458-485
private const GHOST_USER_ID = '00000000-0000-0000-0000-000000000000';

private function resolveUserId(?string $submittedUserId): string
{
    if ($submittedUserId && $submittedUserId !== 'ANONYMOUS_GHOST') {
        $user = User::where('supabase_auth_user_id', $submittedUserId)->first();
        if ($user) return $user->id;
    }
    return $this->ensureGhostUser();
}

private function ensureGhostUser(): string
{
    return User::firstOrCreate(
        ['supabase_auth_user_id' => self::GHOST_USER_ID],
        [
            'name' => 'Anonymous Ghost',
            'email' => 'ghost@likaslens.local',
            'role' => 'ghost',
            'trust_score' => 0,
            'reward_points_balance' => 0,
            'password' => bcrypt(Str::random(32)),
        ]
    )->id;
}

Photo Capture
User captures photo via camera or file upload. On mobile-pwa, captureWithStamp() draws video frame + AR metadata overlay onto canvas.
2
Client-Side EXIF Strip

3
Ghost Mode Toggle
If Ghost Mode is ON: frontend omits user_id; mobile-pwa omits user_id, latitude, longitude.
4

POST /api/reports with base64 image + metadata. Public endpoint — no auth required. Rate limited at 10/min.
5
Server-Side EXIF Strip (Defense-in-Depth)
stripExifMetadata() via Imagick (preferred) or GD fallback. Runs on EVERY submission, not just Ghost Mode. Additional GD re-encode for JPEG/PNG.

7
Database Transaction
Creates Ticket (reporter = ghost user), TicketEvidence (with exif_removed_at), Report (user_id = ghost).
8
Post-Submission Pipeline
Timeline event fired (actor = null for ghost). Notifications skipped. Achievements skipped. Blockchain hash excludes reporter identity. Chain service links to nearby reports.

7. Known Vulnerabilities & Gaps

7.1 Frontend GPS Leak (HIGH)

VULN-01: Frontend sends GPS in Ghost Mode

Severity: HIGH

Location: apps/frontend/src/app/[locale]/report/page.tsx:307

Description: The frontend report page constructs the payload with latitude and longitude always included, regardless of Ghost Mode. Only the mobile-pwa correctly omits them.

Impact: A Ghost Mode report submitted via the web frontend still contains exact GPS coordinates in the API request body, linking the report to a specific location.

Fix: Add conditional logic: latitude: isGhostMode ? undefined : latitude

7.2 No Location Fuzzing (MEDIUM)

VULN-02: No barangay-centroid replacement

Severity: MEDIUM

Description: Ghost Mode either sends exact GPS or omits GPS entirely. There is no intermediate "fuzzy location" that snaps to the nearest barangay centroid for privacy-preserving analytics.

Impact: Reports without GPS cannot be included in spatial analytics (heatmaps, clustering). This limits the utility of Ghost Mode reports for environmental monitoring.

7.3 Service Worker Offline Queue (LOW)

VULN-03: Offline queue stores raw image data

Severity: LOW

Location: apps/mobile-pwa/public/sw.js:23-79

Description: The service worker queues the full request body (including base64 image) in IndexedDB when offline. EXIF stripping only happens when the queued report is eventually submitted.

Mitigation: The image is already EXIF-stripped at capture time (canvas re-encode), so the queued data should not contain EXIF. However, if a user uploads a pre-existing photo with EXIF while offline, the metadata persists in IndexedDB until submission.

7.4 Triple EXIF Implementation (LOW)

VULN-04: Code duplication — not DRY

Severity: LOW (code quality, not security)

Files:

  • apps/frontend/src/utils/exif-stripper.ts — standalone utility
  • apps/frontend/src/utils/supabase/storage.ts:23-45 — profile uploads
  • apps/frontend/src/app/[locale]/report/page.tsx:98-120 — inline duplicate

Impact: If the stripping technique needs updating, all 3 locations must be patched independently. Risk of inconsistency.

7.5 Server-Side Fallback Warning (INFO)

VULN-05: EXIF not stripped if Imagick AND GD are unavailable

Severity: INFO

Location: ReportController.php:577

Description: If neither Imagick nor GD PHP extensions are installed, the server returns the image unchanged with a warning log. This is a degraded state, not a bug — but operators must ensure at least one extension is available.

9. Recommendations

Priority 1 — Fix Frontend GPS Leak

CRITICAL: Omit GPS from frontend Ghost Mode payload
// apps/frontend/src/app/[locale]/report/page.tsx:307
// BEFORE:
const payload = { base64Image: cleanedImage, latitude, longitude };

// AFTER:
const payload: Record<string, unknown> = { base64Image: cleanedImage };
if (!isGhostMode) {
  payload.latitude = latitude;
  payload.longitude = longitude;
}

Priority 2 — Add Location Fuzzing

HIGH: Implement barangay-centroid replacement

When Ghost Mode is active, replace exact GPS with the nearest barangay centroid before storage. This enables spatial analytics while protecting reporter location.

Approach: Use a server-side lookup table of barangay centroids. Snap coordinates to nearest centroid within 5km radius.

Priority 3 — Consolidate EXIF Stripping

MEDIUM: DRY up client-side EXIF stripping

Replace the 3 inline implementations with a single shared utility. Import stripExif from @/utils/exif-stripper everywhere.

Priority 4 — Add EXIF Strip Verification Test

LOW: Add test that verifies EXIF is actually removed

The existing test (ReportSubmissionTest.php:45-56) only verifies ghost user creation. Add a test that submits an image with known EXIF data and asserts the stored image has no metadata.

10. Detailed Verdict

Does Ghost Mode Truly Strip EXIF Data?

✅ YES — EXIF is reliably stripped

EXIF metadata is removed at two independent layers:

  1. Client-side: Canvas re-encode produces raw pixel raster with no metadata. This happens before transmission.
  2. Server-side: Imagick stripImage() (lossless) or GD re-encode (fallback) removes any residual metadata. Runs on every submission.

Both layers are functional. The defense-in-depth approach means even if one layer fails, the other provides protection. The exif_removed_at timestamp provides an audit trail.

Is the Reporter Truly Anonymous?

⚠️ MOSTLY — with one significant gap

What's protected:

  • Real name, email, and auth ID are never stored on ghost reports
  • No notifications are sent to the ghost user
  • No achievements or rewards accumulate (prevents correlation)
  • Timeline entries show actor: null
  • Blockchain hash excludes reporter identity
  • EXIF (including device info) is stripped

What's NOT protected (on web frontend):

  • GPS coordinates are still transmitted in the API payload when using the web frontend in Ghost Mode
  • No location fuzzing exists — GPS is either exact or absent

Verdict: The mobile-pwa Ghost Mode provides strong anonymity. The web frontend Ghost Mode has a GPS leak that must be fixed.

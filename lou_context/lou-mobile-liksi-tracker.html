02 — the one real unknown

This isn't a one-line copy-paste, and here's exactly why

I checked apps/mobile-pwa/src/app/[locale]/(app)/layout.tsx directly — it has no isAuthenticated or locale value already wired the way frontend's layout does. locale is easy: it's already being derived from the URL path a few lines up (pathname.split("/")[1]) for routing — reuse that, don't reinvent it. isAuthenticated is the real unknown: the layout already imports createClient from @/lib/supabase/client but never calls it. There's also an existing apps/mobile-pwa/src/app/[locale]/auth directory that almost certainly already knows how to check session state — look there first before writing new auth-detection logic from scratch.

Do this

Check how apps/mobile-pwa/src/app/[locale]/auth determines session state today, and reuse that mechanism (or the already-imported createClient) to compute a real isAuthenticated boolean for the layout.

Don't do this

Don't hardcode isAuthenticated={false} just to ship faster — LGU officers may also use mobile-pwa, and a citizen-only chat would silently regress LGU functionality nobody would notice until a demo.

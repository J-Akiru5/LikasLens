2 · Heatmap gradient — refined, not replaced

The existing 6-stop ramp was a genuine severity gradient, not a placeholder. The one weak seam: high → critical read as two shades of the same red once GPU blur softened the edges at real zoom levels — elevated → high already carried the biggest perceptual jump in the ramp. High moved #ef4444 → #f43f5e (rose, cooler) and critical moved #9f1239 → #7f1d3a (darker, more saturated wine) — applied to enhanced-map.tsx (frontend + mobile), heatmap-widget-deck.tsx, and every legend/pin color that referenced the old values, so the whole stack reads as one severity language again.

3 · GPS-denied submission — fabricated coordinates removed

The location picker (geo-tag-map.tsx) had already stopped setting a fake marker on GPS denial. But the report pages in both apps still fell back to Manila's coordinates at the moment of submission if the user never manually tapped the map — the exact bug this was meant to close, still live.

Before — both apps, finalizeSubmission
latitude: latitude ?? 14.5995,
longitude: longitude ?? 120.9842,
After
latitude,
longitude,
// submission blocked upstream
// if either is null
Product decision — confirmed with Jeff
Block submission. Not the flag-and-accept alternative. A citizen with GPS denied and no manual pin now sees the "Review & Submit" button disabled with an inline explanation, rather than a ticket landing at DENR/DILG with a coordinate nobody visited.

What changed, file by file

  • frontend report/page.tsx — removed the Manila fallback in finalizeSubmission; button disabled without lat/lng; inline warning added.
  • frontend geo-tag-map.tsx — GPS-denial now shows an amber banner ("tap the map to place the pin") instead of failing silently.
  • mobile-pwa report/page.tsx — same submission fix, plus a second fallback removed: the camera EXIF-stamp overlay was burning 0, 0 into the visible photo watermark when GPS wasn't ready. It now prints "LOCATION PENDING" instead.
  • mobile-pwa geo-tag-map.tsx — same GPS-denial banner, ported to its Leaflet implementation.

Nominatim reverse-geocoding was already in place in the frontend's geo-tag-map.tsx for address resolution — no new geocoding work was needed this pass.

5 · Roadmap — inside the MapLibre / deck.gl ecosystem

  1. 01
    3D severity extrusion — deck.gl ColumnLayer or HexagonLayer keyed to urgency score, for a tilt-view of hotspots at the admin dashboard.
  2. 02
    Time-slider playback — scrub incident history over days/weeks using the existing getHeatmap({ days }) param, animating the deck.gl layer's data window.
  3. 03
    Self-hosted vector tiles — drop the CARTO dependency by serving Philippines-scoped tiles (tippecanoe / martin), removing the last external map SLA.
  4. 04
    Offline tile caching — cache the mobile PWA's viewport tiles via service worker for field use with no signal.
Explicitly out of scope
Google Maps is not on this roadmap. It was evaluated and rejected for this cycle — new SDK, new API key, new billing dependency, two days before judging. That stands after judging too: revisit only if a specific, named problem surfaces that MapLibre/deck.gl genuinely cannot solve, not by default.

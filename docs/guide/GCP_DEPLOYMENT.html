Phase 1 — GCP Project & Billing Manual

Create Your GCP Project

This creates the digital "fenced yard" where both services (backend + AI) will live.

One project, two services: Both likaslens-api and likaslens-ai live in this single project. This simplifies billing, IAM, and Artifact Registry — one setup covers both.
1 Go to console.cloud.google.com and log in.
2 Look at the top blue bar. Click the project dropdown (it might say "Select a project").
3 Click New Project in the top right of the modal.
4 Project Name: likaslens → Click Create.
5 Make sure that project is selected in the top blue bar.
6 Search "Billing" in the top search bar. Link your account to activate your 3-month free credits.
Note: Google requires billing to verify you aren't a bot. It will pull from your credits, not your card.

Set Up Billing Budget & Alerts

Important

This is your safety net. If containers stay awake too long or traffic spikes, you'll know immediately — not when the bill arrives.

1 Go to Billing → Budgets & alerts (left sidebar).
2 Click + Create Budget.
3 Name: likaslens-budget
4 Set amount: $10 (or $5 if you want tighter control).
5 Under Alerts, check all three thresholds: 50%, 90%, 100%.
6 Enter your email under Notification recipients → Click Finish.
Why this matters: Cloud Run charges per request + compute time. If a container stays awake or gets hammered with traffic, costs can spike. These alerts give you time to react before your credits run out.

Phase 2 — Enable APIs & Artifact Registry Manual

Enable Artifact Registry

Artifact Registry is the "parking garage" where your Docker containers are stored before Cloud Run loads them.

1 Use the top search bar and search for "Artifact Registry".
2 Click Enable if prompted.
3 Click + Create Repository.
FieldValue
Namelikaslens-repo
FormatDocker
ModeStandard
Location TypeRegion → asia-southeast1 (Singapore)
4 Click Create.
Why Singapore? Closest GCP region to the Philippines for the fastest response times.

Enable Cloud Run API

Cloud Run is where your containers actually run. You just need to turn on the API — nothing else here.

1 Search for "Cloud Run" in the top search bar.
2 Click Enable to turn on the Cloud Run API.
Ignore "Connect Repository": You'll see options to connect GitHub repos or set up Cloud Build. Skip all of that — your GitHub Actions pipeline handles building and pushing containers. You only need the API enabled.
Phase 2B — Neo4j AuraDB (Graph Database) Manual

Create Neo4j AuraDB Free Instance

Neo4j stores your environmental law knowledge graph (hazards → laws → agencies). The free tier gives you 200K nodes and 400K relationships — more than enough.

1 Go to neo4j.com/cloud/aura-free → Click Start Free.
2 Sign up with your email. You'll land on the Neo4j Console.
3 Click Create Instance:
  • Name: likaslens-graph
  • Region: Leave default or choose closest to you
4 Save your credentials immediately (shown once, cannot be retrieved later):
  • NEO4J_URI — looks like neo4j+s://xxxx.databases.neo4j.io
  • NEO4J_USER — usually neo4j
  • NEO4J_PASSWORD — auto-generated, copy this now
5 Save these values — you'll paste them into Cloud Run env vars in Phase 4.
Save your password now! Neo4j only shows the password once during instance creation. If you lose it, you'll need to reset the instance.
Cost: AuraDB Free is truly free forever (no credit card required). 200K nodes, 400K relationships, 1 instance. Your 3-month GCP credits are not used here.
Phase 3 — Service Account (VIP Pass) Manual

Create Service Account

This creates a secure ID badge so GitHub Actions is allowed to upload code to your GCP project.

1 Search for "Service Accounts" (under IAM & Admin) in the top search bar.
2 Click + Create Service Account at the top.
3 Name: github-actions-deployer → Click Create and Continue.
4 Grant these 4 roles using the dropdown:
  • Cloud Run Admin — allows updating the live app
  • Artifact Registry Administrator — allows parking the Docker container
  • Storage Admin — required for uploading
  • Service Account User — required for impersonation
5 Click Done.
Critical: Missing any of these 4 roles will cause the GitHub Actions deploy to fail silently.

Download & Connect the Key

1 Find your new service account in the list. Click the three dots under "Actions" → Manage Keys.
2 Click Add Key → Create new key → Choose JSON → Click Create.
3 A .json file downloads. Guard this with your life — it is the master key to your server.
Security: Never commit this file to git. Never share it in chat. Store it in a password manager.

Connect to GitHub

1 Go to your LikasLens GitHub Repository → Settings → Secrets and variables → Actions.
2 Click New repository secret.
3 Name: GCP_CREDENTIALS
4 Secret: Open that downloaded JSON file in Notepad, copy ALL the text, and paste it here.
5 Click Add secret.

Phase 5 — GitHub Actions CI/CD Automated

Pipeline Is Already Configured

The deployment workflows are already committed to your repo. They will trigger automatically when you push to main.

WorkflowTriggerWhat It Does
gcp-backend-deploy.yml Push to main when apps/backend/** changes CI gate → Trivy scan → Push to Artifact Registry → Deploy to Cloud Run
gcp-ai-service-deploy.yml Push to main when apps/ai-service/** changes CI gate → Trivy scan → Push to Artifact Registry → Deploy to Cloud Run
Test containers are replaced automatically: The sample containers you deployed in Phase 4 are temporary placeholders. When you push to main, GitHub Actions builds your real Docker image and deploys it — the test container is replaced automatically. Your env vars are preserved because they're stored in the Cloud Run service config, not inside the container.

What the Pipeline Does (Step by Step)

  1. CI Gate — Runs Pint (PHP lint), php artisan test, flake8 (Python lint), TypeScript checks
  2. Build — Builds the Docker image from apps/backend/Dockerfile or apps/ai-service/Dockerfile
  3. Trivy Scan — Scans the image for HIGH/CRITICAL vulnerabilities, uploads SARIF to GitHub Security
  4. Google Auth — Authenticates using the GCP_CREDENTIALS secret
  5. Push — Pushes the image to asia-southeast1-docker.pkg.dev/likaslens/likaslens-repo/
  6. Deploy — Tells Cloud Run to swap the sample container for the real code
Phase 6 — Running Seeders Manual

Seed Neo4j Graph Database (Required)

This seeds the graph with 16 PH environmental laws, 18 hazard types, 5 agencies, 3 locations (Iloilo), and all their relationships.

1 Open GCP Cloud Shell (terminal icon >_ at the top right of the GCP console).
2 Clone the repo and install dependencies: 
git clone https://github.com/J-Akiru5/LikasLens.git
cd LikasLens/apps/ai-service
pip install neo4j python-dotenv google-generativeai
3 Set environment variables: 
export NEO4J_URI="neo4j+s://your-instance.databases.neo4j.io"
export NEO4J_USER="neo4j"
export NEO4J_PASSWORD="your-password"
export GOOGLE_API_KEY="your-gemini-key"  # optional, enables vector embeddings
4 Run the seed script: 
python seed_neo4j.py
5 To clear and re-seed (e.g., after schema changes): 
python seed_neo4j.py --drop
What it does: Creates uniqueness constraints, seeds all vertex nodes (laws, hazards, agencies, violations, locations), seeds all edges (GOVERNED_BY, VIOLATES, ENFORCED_BY, CLASSIFIED_AS). If GOOGLE_API_KEY is set, it also creates a vector index and embeds the 16 PH laws for GraphRAG.

Verify in Neo4j Console

1 Go to console.neo4j.io → Open your instance → Query tab.
2 Run: MATCH (n) RETURN labels(n)[0] AS label, count(n) AS count ORDER BY count DESC
3 Expected results: Law (16), HazardType (18), Agency (5), ViolationType (11), Location (3).

Backend Seeders (Optional)

Auto-migrations: The start.sh entrypoint already runs php artisan migrate --force on every container boot. Migrations happen automatically.

To run Laravel seeders (sample data):

gcloud run jobs create seed-job \
  --image asia-southeast1-docker.pkg.dev/likaslens/likaslens-repo/likaslens-backend:latest \
  --command "php,artisan,db:seed,--force" \
  --region asia-southeast1

gcloud run jobs execute seed-job --region asia-southeast1

4. Schema Changes (D1)

Migration: 002_add_category_severity

ColumnTypeNullableDefaultSource
category VARCHAR(100) Yes (initially) NULL Backfilled from ai_analysis_raw->'environmental_assessment'->'indicators'->0->>'type'
severity VARCHAR(20) No (after backfill) 'low' Backfilled from ai_analysis_raw indicators — worst severity across all indicators

Backfill logic: Category extracted from JSONB path ai_analysis_raw->'environmental_assessment'->'indicators'->0->>'type', with fallback to parsing ai_triage_summary text. Severity computed as MAX across all indicator severities (critical=5, high=4, medium=3, low=2, info=1).

Index: ix_tickets_category on category for analytics GROUP BY performance.

Triage Service Changes (D3)

triage_service.py now:

  • Iterates ALL indicators (not just indicators[0])
  • Derives severity as the worst/highest across all detections
  • Persists both category and severity to the ticket on every triage
  • Uses a mapping table to convert category vocabulary to correct Neo4j ViolationType codes
Constraint satisfied: Nothing labelled "severity" is actually ai_confidence. The urgency_score column still stores confidence (renamed labels in UI), but the new severity column carries the real indicator-derived severity.

5. Neo4j Fix (D1b)

Problem

triage_service.py sent category.upper().replace(" ", "_") (e.g. "ILLEGAL_DUMPING") to route_incident(). But seeded ViolationType nodes use different codes (e.g. "SWM-ILLEGAL-DUMPING"). The MERGE (v:ViolationType {code: $violation_code}) query silently created orphan nodes every time.

Fix

Added CATEGORY_TO_VIOLATION_CODE mapping in triage_service.py:

CategoryViolationType Code
illegal_dumpingSWM-ILLEGAL-DUMPING
solid_wasteSWM-ILLEGAL-DUMPING
water_pollutionWATER-UNAUTHORIZED-DISCHARGE
air_pollutionAIR-EMISSION-VIOLATION
deforestationILLEGAL-LOGGING
illegal_burningOPEN-BURNING
sewage_dischargeWATER-UNAUTHORIZED-DISCHARGE
chemical_spillHAZWASTE-HANDLING
noise_pollutionNOISE-POLLUTION

route_incident() also now accepts a severity parameter and sets i.severity on Incident node creation.

Verification required: This fix must be confirmed against a real Neo4j Aura query (not just "no error thrown") before calling it done. Run MATCH (n:ViolationType) RETURN n.code to confirm codes match, then trigger a triage and verify the CLASSIFIED_AS edge forms to an existing node.

7. Analytics Endpoints (Task 2)

New module at apps/ai-service/analytics/ with 4 endpoints under /api/v1/analytics:

GET /hotspots Grid-cell concentration (0.01° ~1km), min cell size 5, dominant category + severity breakdown require_lgu_role

Ghost-Mode Safety Rules (Applied)

  • Never SELECT, GROUP BY, or return IDENTITY_FIELDS (reporter_user_id, reporter_email, reporter_phone, reporter_ip, ghost_mode)
  • Minimum cell size floor of 5 on all location-scoped aggregates (hotspots)
  • Ghost mode count reported as aggregate only — never per-record
  • Grid cells use same fuzz_location() as ghost mode — ghost and non-ghost reports land in same coordinate space

Every Response Includes Meta Block

{
  "total_reports_analyzed": 200,
  "window_days": 30,
  "generated_at": "2026-08-30T08:15:00+00:00"
}

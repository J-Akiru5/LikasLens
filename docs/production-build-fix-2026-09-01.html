1. Root Cause

Prompt 4 removed community_corroboration and geo_within_known_zone from ConfidenceBreakdown in apps/shared/src/types/ticket.ts (now only visual: number). The build-verification step for that prompt only covered apps/shared and apps/admin-portal, not apps/frontend — a scoping gap. 2.3 explainability-panel.tsx — CounterfactualPanel

Problem (type drift): CounterfactualPanel had a locally duplicated three-field prop type instead of importing ConfidenceBreakdown from shared. This let the drift happen silently — the local shape wasn't constrained by the shared type.

Problem (fabricated data): Three of four counterfactual scenarios described signals that were never computed from real data, even before this break. They had hardcoded impact numbers (-0.12, -0.08, +0.08) with no backing signal at any layer. Only "Lower visual confidence" derives its number from a real input (breakdown.visual).

Note: The fabricated counterfactual scenarios predate today's break. They were only surfaced by diagnosing the production build failure. This is the same "never fabricate, remove instead" rule applied consistently with the admin bypass fix earlier today.

function CounterfactualPanel({

  confidence: number;
  breakdown?: ConfidenceBreakdown;  // shared type

  const baseVisual = breakdown?.visual ?? confidence;
  const impact = baseVisual > 0.5
    ? -(baseVisual - 0.5) * 0.5 : 0;
  const newConfidence = Math.max(0, confidence - impact);

  // ...rendered inline, no scenarios array

1. Technical Failing Points — Stability & Error Handling
⚠️ 1.1 Confidence Threshold Too Permissive
apps/ai-service/image_analysis.py:302
The default confidence_threshold=0.25 is dangerously low for a system with legal consequences. A COCO model at 0.25 will produce many false positives on cluttered ASEAN coastal/urban scenes — bottles misidentified as litter, potted plants misidentified as vegetation clearing.
Recommendation: Raise default to 0.50 for the COCO model. Add a --strict mode (0.65+) for deployment in high-legal-risk contexts. The confidence value should flow through to the TicketClassification.confidence field so admins can filter by it.
⚠️ 1.2 No Confidence Aggregation Across Dual Models
apps/ai-service/image_analysis.py:201-226
When _merge_detections replaces a COCO detection with an environmental model detection, it only checks if the env model has higher confidence. There is no composite confidence score. A low-confidence COCO "bottle" can be replaced by a low-confidence env_model "plastic" and still trigger has_environmental_concern.
Recommendation: Add a composite confidence calculation:
composite = max(coco_conf, env_conf) * 0.7 + model_agreement_bonus * 0.3 where model_agreement_bonus is 1.0 if both models agree on hazard type, 0.0 otherwise. Gate has_environmental_concern on composite >= 0.50.
⚠️ 1.3 No Retry/Backoff on Gemini Calls
apps/ai-service/hazard_analyzer.py:157-181
Gemini calls use a single 30s timeout with no retry. Transient 429/503 errors from Google will cascade into 502s during demo or production.
Recommendation: Add exponential backoff with jitter (3 attempts: 1s, 2s, 4s) wrapping the asyncio.wait_for call. ~15 lines of code.
⚠️ 1.4 Routing Learner is File-Based, Not Atomic
apps/ai-service/routing_learner.py:61-70
_persist() uses temp-file-then-rename (good), but _scores is an in-memory dict loaded lazily. Under concurrent uvicorn workers, each worker has its own _scores dict, causing data races and lost resolution records.
Recommendation: For the hackathon, pin uvicorn to --workers 1. For production, move routing scores to PostgreSQL with upsert.
⚠️ 1.5 No Circuit Breaker on AI Service
apps/backend/app/Services/TriageService.php
The backend calls the AI service as "best-effort" (good for resilience), but there is no circuit breaker. If the AI service is down, every report submission waits for the full HTTP timeout before falling back.
Recommendation: Add a simple in-memory circuit breaker: after 3 consecutive AI failures, skip the AI call for 60s and return "triage-pending" status. Prevents 30s+ latency spikes.
⚠️ 1.6 Missing Ground Truth Dataset
apps/ai-service/eval_metrics.py:159
The eval harness references apps/ai-service/test_data/ground_truth.jsonl but this file does not exist. The judges specifically asked for measured metrics on real ASEAN imagery.
Recommendation: Create apps/ai-service/test_data/ with 200+ labeled images: 50 illegal dumping, 50 open burning, 50 water pollution, 50 clean negatives.

3. Cross-Border Scalability — Legal Graph Layer Across ASEAN

Current State

The graph is 100% Philippines-specific: 16 Philippine laws, 5 Philippine NGOs in Western Visayas, 3 Philippine locations. However, the architecture already has the right primitives:

Tenant.country_code — multi-tenant isolation
CountryCode.eco_credit_rate — per-country economics
SlaConfig.forViolation($code, $country) — scoped SLAs
jurisdictionCode property on graph vertices
X-Tenant-Slug header in OpenAPI

Recommended Cross-Border Graph Schema

ASEAN_LAWS = {
    "PH": [...],  # existing 16 laws
    "MY": [
        {"code": "ACT-672", "title": "Environmental Quality Act 1974", ...},
        {"code": "ACT-733", "title": "Environmental Quality (Prescribed Premises) Regulations", ...},
    ],
    "ID": [
        {"code": "UU-32-2009", "title": "Environmental Protection and Management Law", ...},
    ],
    # ... TH, VN, SG, BN, KH, LA, MM
}

Graph Traversal Must Be Jurisdiction-Scoped

apps/ai-service/graph_rag.py — hybrid_retrieve
Current graph traversal queries do not filter by jurisdiction. A query for illegal_dumping in Malaysia would still return Philippine laws.
Recommendation: Add jurisdiction parameter to every Cypher query: 
MATCH (l:Law)-[:VIOLATES]-(h:HazardType {code: $hazard_code})
WHERE l.jurisdictionCode = $jurisdiction
MATCH (l)-[:ENFORCED_BY]->(a:Agency)
RETURN l, a

4. Edge Cases — LGU Unresponsive Workflow

Current State

The SLA system (SlaService.php) already has response/resolution deadlines, breach detection, and escalation. What is missing: automatic re-routing, citizen notification, public scoreboard impact, and escalation chains.

Recommended Workflow

T+0h
Report auto-routed to primary LGU (based on location + routing learner)
T+24h
SLA response deadline breached
  • System attempts re-route to secondary LGU (routing_learner.get_best_lgu)
  • Citizen notified: "Your report is being reassigned"
T+72h
SLA resolution deadline breached
  • Ticket escalated to admin
  • Public scoreboard flags ticket as "overdue"
  • Citizen notified: "Your report has been escalated"
T+168h
7 days — no resolution
  • Ticket marked "unresolved - escalated to regional authority"
  • Public accountability record created
  • Citizen can provide supplementary evidence

Implementation Details

Backend Changes Required
  1. Add reassigned_at and reassigned_to fields to Ticket
  2. Add escalation_level enum: none, lgu, admin, regional, national
  3. Modify SlaService::runEscalationCheck() to re-route at response breach, escalate at resolution breach
  4. Fire notification events (even if notification system is TODO)
  5. Add overdue counts to public scoreboard query
View example notification events 
event(new TicketReassigned($ticket, $oldLgu, $newLgu));
event(new TicketEscalated($ticket, $escalationLevel));
event(new TicketOverdue($ticket));
View public scoreboard SQL 
SELECT lgu_id,
       COUNT(*) FILTER (WHERE status = 'resolved') as resolved,
       COUNT(*) FILTER (WHERE sla_resolution_breached = true) as overdue
FROM tickets GROUP BY lgu_id

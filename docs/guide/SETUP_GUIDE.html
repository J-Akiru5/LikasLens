1. Rotate Supabase Keys

Why: The real Supabase anon key is in .env.local files and possibly in git history. Even though the hardcoded fallback was removed from config/services.php, the key itself may still be exposed.

Step 1 — Regenerate the key

  1. Go to supabase.com → Your Project → Settings → API
  2. Click "Regenerate" on the anon / public key
  3. Copy the new key (starts with eyJ...)

Step 2 — Update all .env.local files

Replace NEXT_PUBLIC_SUPABASE_ANON_KEY in these files:

apps/frontend/.env.local
apps/mobile-pwa/.env.local
apps/admin-portal/.env.local 
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_new_key_here

Step 3 — Verify .gitignore

Make sure each app's .gitignore includes .env.local:

# In apps/frontend/.gitignore, apps/mobile-pwa/.gitignore, apps/admin-portal/.gitignore:
.env.local

Step 4 — Check for leaked credentials in docs

The audit found a database password (RZCpSUDmyRJ1uKVH) and Supabase URL in these files. Search and replace with placeholders:

# Search for leaked credentials:
grep -rn "RZCpSUDmyRJ1uKVH" .
grep -rn "sfklmmtimelotqvrldni" .

# Replace with placeholders in:
#   README.md
#   AZURE_DEPLOYMENT.md
#   Any other docs

Step 5 — Purge from git history (optional but recommended)

If .env.local was ever committed, the old key is permanently in git history. Use BFG Repo-Cleaner to remove it. 
# Install BFG (requires Java)
java -jar bfg.jar --delete-files .env.local
git reflog expire --expire=now --all && git gc --prune=now --aggressive

2. Push Notifications

Users can't receive alerts when their reports are verified or resolved. Here's how to add Web Push support.

Step 1 — Generate VAPID keys

npx web-push generate-vapid-keys

Save the output. Add to your .env files:

VAPID_PUBLIC_KEY=BNx...
VAPID_PRIVATE_KEY=abc...
VAPID_SUBJECT=mailto:admin@likaslens.org

Step 2 — Backend: Create push subscriptions table

cd apps/backend
php artisan make:migration create_push_subscriptions_table

Schema:

Schema::create('push_subscriptions', function (Blueprint $table) {
    $table->id();
    $table->uuid('user_id')->constrained('users')->cascadeOnDelete();
    $table->text('endpoint');
    $table->text('p256dh');
    $table->text('auth');
    $table->timestamps();
});
php artisan migrate

Step 3 — Backend: Install web-push library

cd apps/backend
composer require minishlink/web-push

Step 4 — Backend: Create controller + service

php artisan make:controller PushSubscriptionController
php artisan make:service PushNotificationService

PushSubscriptionController — two endpoints:

  • POST /api/push/subscribe — stores subscription (endpoint, keys, user_id)
  • DELETE /api/push/subscribe — removes subscription by endpoint

PushNotificationService — one method:

  • sendNotification($subscription, $payload) — sends push via minishlink/web-push

Call PushNotificationService::sendNotification() in TicketController when status changes to verified or resolved.

Step 5 — Mobile PWA: Subscribe to push

Create apps/mobile-pwa/src/lib/push-manager.ts:

export async function subscribeToPush() {
  const registration = await navigator.serviceWorker.ready;
  const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY,
  });

  await fetch("/api/push/subscribe", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(subscription),
  });
}

Step 6 — Mobile PWA: Handle push in service worker

Add to apps/mobile-pwa/public/sw.js:

self.addEventListener("push", (event) => {
  const data = event.data.json();
  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
      icon: "/icons/icon-192x192.png",
      badge: "/icons/icon-192x192.png",
      data: { url: data.url },
    })
  );
});

self.addEventListener("notificationclick", (event) => {
  event.notification.close();
  event.waitUntil(clients.openWindow(event.notification.data.url));
});

3. Wire Up Translations (i18n)

The i18n infrastructure exists (next-intl + 6 locale files) but most pages hardcode English text.

Step 1 — Find hardcoded strings

grep -rn "\"[A-Z]" apps/mobile-pwa/src/app --include="*.tsx" | grep -v "import\|className\|type\|interface"

Step 2 — Add keys to locale files

For each string, add entries to all 6 files:

apps/mobile-pwa/src/i18n/messages/en.json
apps/mobile-pwa/src/i18n/messages/fil.json
apps/mobile-pwa/src/i18n/messages/vi.json
apps/mobile-pwa/src/i18n/messages/id.json
apps/mobile-pwa/src/i18n/messages/ms.json
apps/mobile-pwa/src/i18n/messages/ta.json

Example in en.json:

{
  "Report": {
    "title": "Submit Report",
    "ghostMode": "Ghost Mode",
    "selectType": "Select incident type"
  }
}

Step 3 — Replace hardcoded text in pages

import { useTranslations } from "next-intl";

export default function ReportPage() {

}

Step 4 — Auto-translate with Gemini

The shared package has a useGeminiChat hook. Use it to generate translations for non-English locales by prompting: "Translate [English text] to [language], return only the translation."

5. Server-Side PDF Generation

Current PDF export uses client-side html2canvas which has quality issues and large bundle size.

Option A: Puppeteer (full-page rendering)

pnpm --filter frontend add puppeteer-core

Create apps/frontend/src/app/api/export-pdf/route.ts:

import puppeteer from "puppeteer-core";

export async function GET() {
  const browser = await puppeteer.launch({
    executablePath: process.env.CHROME_PATH || "/usr/bin/chromium",
  });
  const page = await browser.newPage();
  await page.goto("http://localhost:3000/dashboard/analytics", {
    waitUntil: "networkidle0",
  });
  const pdf = await page.pdf({ format: "A4", printBackground: true });
  await browser.close();

  return new Response(pdf, {
    headers: {
      "Content-Type": "application/pdf",
      "Content-Disposition": 'attachment; filename="analytics-report.pdf"',
    },
  });
}

Option B: @react-pdf/renderer (React-native PDF)

pnpm --filter frontend add @react-pdf/renderer

Create a PDF document component and render it server-side. Better for structured reports, worse for complex layouts.

6. Accessibility Improvements

Step 1 — Run automated audit

pnpm --filter frontend add -D @axe-core/react

Add <AxeProvider> to the app layout in dev mode. Check browser console for warnings.

Step 2 — Fix common issues

  • Add aria-label to icon-only buttons (search, close, theme toggle)
  • Add role="alert" to toast notifications (already done in shared)
  • Ensure all <img> tags have alt text
  • Add aria-expanded to collapsible sections
  • Add skip-to-content link: 
    <a href="#main-content" className="sr-only focus:not-sr-only">
  Skip to content
</a>

Step 3 — Keyboard navigation

  • Tab through all forms — ensure logical order
  • Modals should trap focus (the shared Modal already does this)
  • Escape key closes modals (already done in shared)
  • Arrow keys navigate dropdown menus (partially done)

Step 4 — Color contrast

Check all text against backgrounds using WebAIM Contrast Checker. The design tokens already have WCAG-compliant defaults, but custom one-off colors may fail.

Priority Order

  1. Rotate Supabase keys — do this TODAY. The longer the old key stays active, the greater the risk.
  2. Push notifications — improves user engagement significantly.
  3. i18n wiring — needed for Filipino and other language users.
  4. Privacy/Terms pages — needed before any app store submission.
  5. PDF generation — nice to have for admin reports.
  6. Accessibility — incremental, can be done over time.

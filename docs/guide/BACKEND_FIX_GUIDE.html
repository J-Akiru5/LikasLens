LikasLens Backend Fix & Configuration Guide

This guide resolves the 401 Unauthorized (notifications) and 500 Internal Server Error (report submission) errors by walking you through the required backend configuration steps.

ERROR 1: 401 Unauthorized on /api/notifications The notifications endpoint requires authentication via Sanctum. The Supabase access token must be sent as a Bearer token in the Authorization header.
ERROR 2: 500 Internal Server Error on POST /api/reports The report submission fails on the backend. The most likely causes are: missing APP_KEY, database not migrated, GD PHP extension missing, or Supabase S3 storage misconfigured.

Prerequisites

Before starting, ensure you have:

  • PHP 8.2+ with Composer
  • Access to your Supabase project dashboard
  • The backend deployed (locally or on Google Cloud Run)
  • Your frontend .env file configured with NEXT_PUBLIC_API_URL, NEXT_PUBLIC_SUPABASE_URL, and NEXT_PUBLIC_SUPABASE_ANON_KEY

1Generate APP_KEY

REQUIRED — Most common cause of 500 errors If APP_KEY is empty, Laravel cannot encrypt cookies, sessions, or tokens. This causes cryptic 500 errors on any authenticated request.

Local Development

# Navigate to the backend directory
cd apps/backend

# Generate a new APP_KEY
php artisan key:generate

# This will update your .env file automatically:
# APP_KEY=base64:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Google Cloud Run (Production)

Set the APP_KEY as an environment variable in your Cloud Run service:

# Generate a key locally first
php artisan key:generate

# Copy the generated key and set it in Cloud Run
gcloud run services update likaslens-api \
  --region=asia-southeast1 \
  --set-env-vars="APP_KEY=base64:your_generated_key_here"
Important: Never commit the real APP_KEY to Git. Always set it via environment variables in production.

2Configure Database Connection

Using Supabase PostgreSQL (Recommended)

Get your database credentials from the Supabase dashboard → Project Settings → Database:

# apps/backend/.env
DB_CONNECTION=pgsql
DB_HOST=db.your-project-ref.supabase.co
DB_PORT=5432
DB_DATABASE=postgres
DB_USERNAME=postgres
DB_PASSWORD=your_supabase_database_password

Using SQLite (Local Fallback)

For quick local testing without Supabase, uncomment the SQLite config:

# apps/backend/.env
# DB_CONNECTION=pgsql
# DB_HOST=db.your-project-ref.supabase.co
# ...

DB_CONNECTION=sqlite
# This creates database/database.sqlite automatically
Supabase Connection Pool: If you're using Supabase's connection pooler (pgBouncer), use port 6543 instead of 5432, and add DB_POOL_MODE=transaction if configured.

3Run Migrations & Seeders

REQUIRED — The ResolveTenant middleware runs on EVERY API request If the tenants table doesn't exist, ALL API requests (including POST /api/reports) will fail with 500 before reaching the controller. 
cd apps/backend

# Run all migrations
php artisan migrate

# Check migration status
php artisan migrate:status

# Seed the default tenant (REQUIRED for multi-tenancy)
php artisan db:seed --class=TenantSeeder

# Seed demo data (optional, for testing)
php artisan db:seed --class=DemoDataSeeder

What the TenantSeeder creates:

  • A default tenant with slug default — this is what ResolveTenant middleware looks up on every request
  • Without this, Tenant::current() returns null and scoped queries may fail

4Install GD PHP Extension

BUG IN CONTROLLER — Lines 107-127 of ReportController.php The report controller calls imagecreatefromstring(), imagejpeg(), and imagepng() without checking if the GD extension is loaded. If GD is missing, this throws a fatal Error: Call to undefined function which is caught by the outer try/catch and returned as a 500.

Check if GD is installed

php -m | findstr gd    # Windows
php -m | grep gd       # Linux/Mac

Install GD

# Ubuntu/Debian
sudo apt-get install php8.2-gd
sudo systemctl restart php8.2-fpm

# Windows (php.ini)
# Uncomment: extension=gd

# Docker — add to your Dockerfile
RUN apt-get update && apt-get install -y libpng-dev libjpeg-dev \
    && docker-php-ext-install gd

# Verify installation
php -r "var_dump(extension_loaded('gd'));"
Also recommended: Install Imagick for better EXIF stripping: sudo apt-get install php8.2-imagick

5Configure Supabase S3 Storage

The backend stores evidence images in Supabase S3-compatible storage. If credentials are wrong, the $disk->put() call throws and causes a 500.

Get credentials from Supabase Dashboard

  1. Go to Supabase Dashboard → Project Settings → Storage
  2. Click "New access key" under S3 Connection
  3. Copy the Access Key ID and Secret Access Key

Set in .env

# apps/backend/.env
SUPABASE_S3_ENDPOINT=https://your-project-ref.storage.supabase.co/storage/v1/s3
SUPABASE_S3_ACCESS_KEY=your_actual_access_key
SUPABASE_S3_SECRET_KEY=your_actual_secret_key
SUPABASE_S3_REGION=ap-southeast1
SUPABASE_STORAGE_BUCKET=likaslens-evidence

Create the storage bucket

In Supabase Dashboard → Storage, create a bucket named likaslens-evidence and set it to Private (evidence images should not be public).

Fallback for local dev: If you don't want to configure S3, just set FILESYSTEM_DISK=local and leave the SUPABASE_S3_* vars blank. The controller will use local disk storage.

6Configure Sanctum (Authentication)

REQUIRED for 401 fix The notifications endpoints (/api/notifications, /api/notifications/unread-count) are protected by the auth:sanctum middleware. The frontend must send a Bearer token.

How auth works in LikasLens

  1. User logs in via Supabase Auth on the frontend
  2. Frontend gets a Supabase access_token (JWT)
  3. Frontend sends this token as Authorization: Bearer <token> to the Laravel API
  4. Laravel's custom middleware validates the Supabase JWT and resolves the user

Backend .env — Sanctum stateful domains

# apps/backend/.env
SANCTUM_STATEFUL_DOMAINS=localhost,localhost:3000,127.0.0.1,127.0.0.1:8000,::1,likaslens.syntaxure.dev

Add your deployed frontend domain to this list (comma-separated).

CORS Configuration

Ensure your Laravel CORS config allows the frontend origin:

# apps/backend/config/cors.php
'paths' => ['api/*'],
'allowed_methods' => ['*'],
'allowed_origins' => [
    'http://localhost:3000',
    'https://likaslens.syntaxure.dev',
    'https://your-frontend-domain.vercel.app',
],
'allowed_headers' => ['*'],
'exposed_headers' => [],
'max_age' => 0,
'supports_credentials' => true,

What changed in the frontend code

The following fixes have been applied to the frontend codebase:

  • Report page (apps/frontend/src/app/[locale]/report/page.tsx): Now uses laravelPost() instead of raw fetch(). This automatically adds the Authorization: Bearer header, credentials: "include" for cookies, multi-tenant X-Tenant-Slug header, and 401 auto-refresh logic.
  • Notifications hook (apps/shared/src/hooks/useNotifications.ts): Now accepts a token option and passes it to all API calls.
  • Dashboard layout (apps/frontend/src/components/layout/dashboard-layout-wrapper.tsx): Now retrieves the Supabase session token and passes it to useNotifications().
  • API client wrappers (apps/shared/src/api/client.ts): All convenience functions (fetchNotifications, fetchUnreadCount, etc.) now accept an optional token parameter.

Docker Deployment Quick Reference

If deploying the backend via Docker (Google Cloud Run), ensure your Dockerfile installs GD:

# In apps/backend/Dockerfile, ensure GD is installed
RUN apt-get update && apt-get install -y \
    libpng-dev \
    libjpeg-dev \
    libfreetype6-dev \
    && docker-php-ext-configure gd --with-freetype --with-jpeg \
    && docker-php-ext-install gd pdo pdo_pgsql

# Set APP_KEY via Cloud Run env vars (NOT in Dockerfile)
ENV APP_KEY=""
# The actual key is injected at runtime via:
# gcloud run services update ... --set-env-vars="APP_KEY=base64:..."

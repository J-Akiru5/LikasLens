🌿 LikasLens Offline System

How camera reports, offline queue, IndexedDB persistence, and production syncing work — explained.

1. Submitting a Report While Offline

When you tap Submit on the Report page and the browser detects navigator.onLine === false, the report is not sent to the server. Instead, it's saved locally.

📷 Take Photo → ✏️ Fill Details → ⬇️ Tap Submit → 💾 IndexedDB → 📋 Queued Securely

The toast appears: "You are offline. Report queued securely."

📦 What gets saved in IndexedDB

  • base64Image — the full photo (can be several MB)
  • latitude / longitude — GPS coordinates
  • report_type — e.g. waste_dumping, water_pollution
  • description — the user's notes
  • UUID — auto-generated unique ID
  • queuedAt — ISO-8601 timestamp

The code lives at apps/shared/src/lib/offline-queue.ts and is shared between the mobile PWA and frontend web app.

2. Where the Data Lives

Primary storage: IndexedDB — a full NoSQL database built into every modern browser.

🗄️ indexedDB
└── 📁 likaslens-offline <-- database name
└── 📂 report-queue <-- object store
├── 📄 { id: "uuid-1", payload: {...}, queuedAt: "2026-..." }
├── 📄 { id: "uuid-2", payload: {...}, queuedAt: "2026-..." }
└── 📄 ...

Fallback: If IndexedDB is unavailable (e.g. private browsing in some browsers), the data is saved to localStorage under the key likaslens_offline_reports.

3. Does the Queue Survive Closing the App?

Yes. IndexedDB is persistent disk storage — it's not in-memory. Here's exactly what survives:

Action Queue survives? Why
Close the browser tab ✅ Yes IndexedDB is on disk, not in RAM
Close the browser entirely ✅ Yes Browser profile storage persists
Restart your computer ✅ Yes Same — it's in the browser's local data directory
Close the installed PWA app ✅ Yes PWAs share the same browser profile storage
Reopen the PWA tomorrow, offline ✅ Yes Data is still there untouched
Reopen weeks later, offline ✅ Yes No expiration — sits until synced or deleted
Clear browser cache / site data ❌ No User explicitly wiped it

The offline queue uses core web platform APIs (IndexedDB, navigator.onLine, window.addEventListener('online')) — these work in any browser, with or without PWA installation.

5. Production Flow — Step by Step

🟡 Phase 1: User is offline

  1. User opens the app (loads via browser cache if PWA is installed)
  2. Takes a photo, fills in details, taps Submit
  3. App checks navigator.onLine → false
  4. queueReport(payload) writes to IndexedDB immediately
  5. Toast: "You are offline. Report queued securely."

🟢 Phase 2: User comes back online

Nothing happens automatically. Sync is manual-only by design.

The window 'online' event fires, updates the isOnline state, and shows a toast: "Connection restored." — but no reports are synced until the user explicitly taps Sync Now.

🟣 Phase 3: App is closed for days

Nothing happens — the queue sits safely in IndexedDB. When the user reopens the app:

  1. Dashboard loads → calls getQueueCount()
  2. If count > 0, the amber offline card appears
  3. User taps → reviews queue → taps Sync Now
  4. Reports are sent to the server and removed from the queue

8. Design Decisions & Notes

⚠️ Storage quota

Base64 images can be several MB each. IndexedDB has a browser-imposed quota (typically 50 MB–500 MB depending on the browser). If a user queues dozens of high-res photos offline, they could hit this limit. The queueReport() function will throw if the quota is exceeded — a graceful error toast for this case would be a good future improvement.

✅ Manual-only sync by design

Sync is only triggered by the user tapping the Sync Now button on the /offline-queue page. There is no auto-flush, no background sync, and no automatic retry. This is intentional — for environmental evidence where photo integrity matters, manual control prevents silent data loss.

Auto-flush and auto-retry were removed from both the frontend and mobile-pwa report pages. The online event only updates the isOnline state and shows a connection toast — nothing more.

📱 Queue page exists in both frontend and mobile-pwa

The /offline-queue page with Sync Now, progress bar, clear/delete, and error handling has been added to both apps/mobile-pwa and apps/frontend. The Dashboard in both apps shows an amber card linking to the queue when reports are pending.

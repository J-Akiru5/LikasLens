Task 2: Add Barangay-Centroid GPS Fuzzing
HIGH 4-6h Dev 3 (Charlyn)

Problem: Ghost Mode either sends exact GPS or omits GPS entirely. There is no "fuzzy location" for privacy-preserving spatial analytics. Reports without GPS cannot appear on heatmaps or be clustered.

Solution: When Ghost Mode is active, snap GPS coordinates to the nearest barangay centroid before storage. This gives a ~1-5km accuracy area that is still useful for analytics but does not pinpoint the reporter.

Implementation Steps

  • Create a barangay_centroids table with columns: id, name, province, latitude, longitude
  • Seed table with PH barangay centroid data (PSGC dataset — ~42,000 barangays)
  • Create LocationFuzzService with method toCentroid(lat, lng): {lat, lng}
  • Use Haversine formula to find nearest centroid within 10km radius
  • In ReportController::store(), after user resolution, if ghost mode: call LocationFuzzService
  • Store fuzzed coordinates on the tickets and reports tables
  • Add location_fuzzed: true field to tickets table for audit trail
  • Update OpenAPI schema with location_fuzzed boolean on Ticket response
  • Test: submit ghost report with known GPS, verify stored coordinates match nearest barangay centroid
Files Involved

Task 5: Strip EXIF in Offline Queue Before Storage
LOW 2-3h Dev 1 (Lou)

Problem: The service worker offline queue (sw.js:23-79) stores the full request body in IndexedDB. If a user uploads a pre-existing photo with EXIF while offline, the metadata persists in IndexedDB until the queued report is eventually submitted.

Mitigation: The image is already EXIF-stripped at capture time (canvas re-encode), so most queued data should not contain EXIF. However, for defense-in-depth, strip EXIF before queuing.

Implementation Steps

  • In the service worker fetch interceptor for POST /api/reports, clone the request body
  • Parse the JSON body, extract base64Image
  • Use OffscreenCanvas to re-encode the image (strips EXIF) before queuing
  • Store the cleaned body in IndexedDB instead of the raw body
  • Note: OffscreenCanvas is available in service workers in Chrome 105+ and Safari 16.4+
  • For browsers without OffscreenCanvas, fall back to storing as-is (server-side strip will catch it)
  • Test: queue a report offline with a photo containing EXIF, go online, verify stored image has no EXIF
Files Involved
  • apps/mobile-pwa/public/sw.js — modify fetch interceptor (lines 111-128)

1. Problem Statement

Two confirmed authorization gaps existed in the Liksi chat pipeline:

  • Persona spoofing: Any caller could set context_mode="admin" or inject an arbitrary system_prompt in the request body. The server trusted these client-provided fields without verification.
  • Missing auth token plumbing: The frontend's API route (route.ts) forwarded zero auth headers to the AI service. Every request appeared anonymous regardless of the user's actual session.

2. Authorization Boundary (Before → After)

InputBeforeAfter
context_mode Untrusted — client-controlled Server-derived from JWT role
system_prompt Untrusted — client-controlled Server-computed — field removed
locale Sent as system_prompt prefix Preference only — validated against allow-list
Supabase Bearer token Never forwarded Extracted from cookie → forwarded as Authorization
X-API-Key (service credential) Never sent Sent when AI_SERVICE_API_KEY is configured

3. Files Changed

3.1 apps/ai-service/services/liksi_service.py

Changes:

  • Added VALID_LOCALES tuple: ("en", "fil", "vi", "id", "ms", "ta", "th")
  • Added LOCALE_INSTRUCTIONS dict mapping each locale to its language instruction string
  • Added validate_locale(locale) — returns "en" for unknown locales (safe fallback, no injection)
  • Extended get_system_prompt(context_mode, locale="en") — composes persona prompt + locale instruction server-side

Key design: Locale interpolation never uses raw client input. The function validates against the allow-list first, so an attacker sending "locale": "<script>" gets safely defaulted to English.

3.2 apps/ai-service/routers/liksi.py

Changes:

  • Removed system_prompt and context_mode from LiksiChatRequest — they are no longer accepted from the client
  • Added locale: str = "en" field (language preference only)
  • Added _LGU_ROLES set: {"lgu_officer", "admin", "super_admin", "analyst"}
  • Derives role from token.get("user_metadata", {}).get("role", "citizen") — same pattern as require_lgu_role
  • Sets context_mode = "lgu" if role ∈ LGU_ROLES, else forces "citizen"
  • Always computes system_prompt via get_system_prompt(server_context_mode, validated_locale)
  • Returns server-derived context_mode in response (not body.context_mode)
# Server-authoritative persona derivation
if token:
    role = token.get("user_metadata", {}).get("role", "citizen")
else:
    role = "citizen"

if role in _LGU_ROLES:
    context_mode = "lgu"
else:
    context_mode = "citizen"

system_prompt = get_system_prompt(context_mode, validated_locale)

3.3 apps/shared/src/lib/ai-gateway.ts

Changes:

  • Added apiKey?: string to AIGatewayConfig
  • Added locale?: string and authToken?: string to ChatRequest
  • Removed context_mode and system_prompt from ChatRequest
  • createAIGatewayFromEnv() reads AI_SERVICE_API_KEY from env
  • forwardRequest() sends three distinct headers:
    • Content-Type: application/json (always)
    • Authorization: Bearer <token> (when user session exists)
    • X-API-Key: <key> (when service key configured)
  • pingHealth() also sends X-API-Key when configured
  • authToken is stripped from the JSON body before sending (not leaked to AI service)

  • Sends locale instead of context_mode and system_prompt

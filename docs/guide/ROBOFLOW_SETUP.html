Roboflow Setup Guide

Configure hosted waste detection via Roboflow's Serverless Inference API — LikasLens Hackathon Edition

Overview

Hackathon Setup

This guide walks you through integrating a pre-trained garbage/litter detection model from Roboflow Universe into LikasLens's AI service. You will:

  • Create a free Roboflow account and get an API key
  • Pick a public waste detection model (no training required)
  • Add credentials to apps/ai-service/.env
  • Verify the integration works end-to-end
Time estimate: ~30 minutes for account + model selection. The code implementation (roboflow_client.py) is handled separately.

Phase 1 — Create Roboflow Account & Get API Key

Step 1: Create a Free Roboflow Account

Required
1 Go to app.roboflow.com and click Sign Up.
2 Sign up with your email, Google, or GitHub. The free tier is sufficient for the hackathon.
3 After verifying your email, you'll land on the Roboflow dashboard.
Free tier includes: $60/month in inference credits (~60,000 API calls). More than enough for the hackathon and early testing.

Step 2: Generate an API Key

Required
1 In the Roboflow dashboard, click your profile icon (top right) → Settings.
2 Navigate to the API Keys section in the left sidebar.
3 Click Create Private API Key. Name it something like likaslens-dev.
4 Copy the API key immediately. It will only be shown once.
Keep this secret. Never commit the API key to Git. It goes in your local .env file only. 
Format: looks like a long alphanumeric string, e.g.
aB3dE5fG7hI9jK1lM3nO5pQ7rS9tU1vW3xY5zA7b
Phase 2 — Pick a Waste Detection Model

Browse Roboflow Universe

Required
1 Go to universe.roboflow.com.
2 Search for "garbage detection", "TACO", or "waste detection".
3 Click a project that looks promising. Look for models with:
  • High accuracy (mAP > 0.5)
  • Multiple waste classes (plastic, paper, glass, metal, etc.)
  • Recent training date
  • Good community usage count
4 Go to the Deploy tab of the chosen project.
5 Select Serverless API (not Local or Docker).
6 Copy the Model ID. It looks like: 
project-name/version-number
Examples:
  taco-trash-annotations-in-context/1
  garbage-detection-v3/2
  waste-classification-yolov8/5

Phase 3 — Configure ai-service Environment

Update .env

Required

Add the two Roboflow variables to apps/ai-service/.env:

ROBOFLOW_API_KEY=your_api_key_here
ROBOFLOW_MODEL_ID=taco-trash-annotations-in-context/1

If you don't already have these variables, here's the full list of AI service env vars you should have:

AI_SERVICE_PORT=8001
AI_SERVICE_API_KEY=dev-ai-service-key-change-in-production
GOOGLE_API_KEY=your_gemini_api_key
NEO4J_URI=neo4j+s://your-instance.databases.neo4j.io
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_neo4j_password
CORS_ORIGINS=http://localhost:3000,http://localhost:3001
YOLO_MODEL_PATH=yolov8n.pt
ENV_MODEL_PATH=best.pt
ROBOFLOW_API_KEY=your_roboflow_api_key
ROBOFLOW_MODEL_ID=taco-trash-annotations-in-context/1
LIKASLENS_METRICS_LOG=true
APP_DEBUG=true
Don't change existing values. Only add or update ROBOFLOW_API_KEY and ROBOFLOW_MODEL_ID. Leave everything else as-is.

Roboflow API Access

No extra install needed

The AI service calls Roboflow's Serverless API directly via HTTP using the requests library (already installed). No additional SDK is required.

Why not the inference SDK? The official Roboflow inference package requires Python <3.13. The AI service runs on Python 3.13+, so we use Roboflow's REST API directly at https://serverless.roboflow.com/{model_id}. Same functionality, zero dependency issues.

Phase 4 — Verify Integration

Health Check

Verification

Once the code is wired up, test with these endpoints:

1 Check Roboflow connectivity: 
curl http://localhost:8001/roboflow/health
# Expected: {"status": "ok", "model": "taco-trash-annotations-in-context/1", "roboflow_connected": true}
2 Test with a garbage photo: 
curl -X POST http://localhost:8001/analyze \
  -F "file=@test_garbage.jpg" \
  -F "latitude=10.3157" \
  -F "longitude=123.8854" \
  -H "X-API-Key: dev-ai-service-key-change-in-production"
# Expected: detections array with both COCO and Roboflow results merged
3 Check the response includes Roboflow detections: 
# Look for detections with "source": "roboflow" in the response
# These should have class names like "Plastic", "Bottle", "Bag", etc.

Troubleshooting

Common Issues
SymptomCauseFix
ModuleNotFoundError: No module named 'inference' Trying to use old SDK approach Not needed — AI service uses raw HTTP via requests. Ignore this error if using the current codebase.
401 Unauthorized from Roboflow Wrong or missing API key Check ROBOFLOW_API_KEY in .env
404 Not Found from Roboflow Wrong model ID Verify ROBOFLOW_MODEL_ID matches the Deploy tab exactly
ConnectionError or timeout Roboflow API unreachable Check internet connection. Service falls back to COCO-only if unreachable.
Detections have no source: "roboflow" Roboflow integration not wired yet Ensure roboflow_client.py is implemented and called from image_analysis.py
AI service won't start Missing env vars Check all required env vars are set. Restart after .env changes.

2. The Problem

Six hardcoded fallback values and fabricated metrics were scattered across the dashboard layer, causing the UI to display misleading data when the database returned zero or few records:

3. The Fix

3.1 Source of Truth: admin.ts getDashboardStats()

The central dashboard stats function was rewritten to:

  • Query the users table for actual user count (was hardcoded 840)
  • Derive investigating count from actual ticket statuses (was Math.round(active * 0.4))
  • Remove all || 42, || 18, || 60, || 840 fallbacks
  • Set fabricated metrics to null: avg_response_minutes, avg_response_hours, avg_response_sla, avg_response_progress, avg_response_trend, system_load, system_load_progress, system_load_trend
  • Set ghost_reports to 0 (was Math.round(total * 0.28))
